# Genesis arm planning and grasp evidence

cuRobo V2 plans; the existing Genesis scene alone owns motors, physics and measured stopping. Stop the base before arm planning; mobile whole-body planning is unsupported. ArmMotion/EndEffectors/GraspEvidence have no robot-name branches (wheel-base control remains MOZ1-specific): MOZ1/Panda joints, tools, gains and collision sources are profile data, not defaults for other bodies or hardware.

## Installation and entry point

Use `pip install -e '.[genesis]' --extra-index-url https://download.pytorch.org/whl/cu130` in a dedicated environment. Separately build [cuRobo V2 commit 78fd485](https://github.com/NVlabs/curobo/tree/78fd485fa82d9b9a063fb4985e371814587e666a) using its upstream CUDA instructions (tested version `0.8.0.post1.dev43`). This Apache-2.0 checkout exposes `MotionPlanner`/`MotionPlannerCfg`, not legacy `MotionGen`; its code/assets are not bundled here. Core imports no CUDA planner.
Set `MOZ1_XRDF` to an externally obtained XRDF matching the actual robot URDF, or `CUROBO_FRANKA_CONFIG` to the checkout's Franka config. Resolve `configs/simulators/planning/{moz1,panda}.yaml` with `planning_profile.load_profile` into JSON under `outputs/arm-planning/`; see the [Python example](../../zh/how-to/genesis-arm-planning.md). The loader expands paths/environment variables and records source hashes and exclusion rationale; workers inherit no arbitrary environment variables.
Only the Python `PreviewSettings`/`GenesisPreview.configure` interface accepts `planning_profile` with `robot_mode="moz1_wheels"`. The GUI has no planning configuration control. Fixed-arm loading is not implemented: Panda is a model/planner validation reference, not a runnable preview mode. New bodies need physical loaders and model/FK/collision/execution acceptance. MOZ1 motors must have valid authored limits (example effort=16.5, velocity≥0.6, lower≤-0.61); old zero-limit exports are rejected.

## Actions and recovery

Admitted ground-truth sessions expose `motion.joint`/`motion.tool_pose`, plus `grasp.parallel` when effectors exist; vision/RGB-D sessions do not. `sim_get_robot_state` includes measured joints, tools and per-effector evidence. `move_joint(targets)` uses absolute named radians/metres and holds omitted joints. `move_tool_poses(group, poses, speed=1)` requires all group tools as `[x,y,z,qw,qx,qy,qz]` in configured planning base_link metres/unit quaternion. `open_gripper(width_mm=80, *, effector=None)` / `close_gripper(force_n=None, *, effector=None)` share the hardware action vocabulary. Select a configured effector when multiple grippers exist; legacy single-gripper adapters retain positional width/force calls and reject named selectors. Genesis ignores width/force hints. Payload preconditions/effects use `payload.clear:<name>` / `payload.held:<name>` for named actions; aggregate held means any hand holds, clear requires all hands measured empty. Unknown remains unknown; closing is not grasp confirmation.

In truth snapshots, `robot.effectors[<name>].entity_id` identifies the payload using the same logical ID as `sim_list_entities` and `sim_get_entity_state`. The worker's numeric `object_id` stays in physical evidence and is not exposed in this snapshot. An unregistered payload has `entity_id=null`; this does not change its measured holding state. After release, the ID can remain available for placement verification, so check `holding_payload` and `placement_confirmed` rather than inferring a grasp from the ID alone.
A separate CUDA process is killed on cancellation/90-second deadline. Ownership and leases use existing RPC. Quintic paths are checked for position/analytic derivative extrema and retimed without clipping; motors never teleport. Execution binds scene/model/base/static joints/payload/obstacles, brakes on failure and measures settling. Results separate plan_success/goal_reached/settled/stop_confirmation; numeric thresholds are in the Chinese guide.
Unknown stopping blocks commands and ownership release; unknown payload blocks planning, base motion and reset. Inspect reason/per-effector state and retain `arm-plans/<scene_instance_id>/<plan_id>/` and sibling `execution-<uuid>.json` under the state directory (default `~/.jiuwensymbiosis/genesis-preview`; every reset creates an instance directory). Release only after measured stable support. Persistent readback failure, a missing object or unconfirmed stopping requires an operator to stop/restart the simulation backend and revalidate the world; there is no evidence-clearing bypass or automatic open/retreat. Official hosts disable Recovery/HOME; custom Session hosts must exclude home and disable automatic recovery too. Automatic homing is unsupported. Evidence has no automatic retention policy; archive/clean it only after backend shutdown.
Effectors require independent bounded motors, disjoint contact groups and no overlap with arm joints; mimic followers remain passive. The supplied MOZ1/Panda profiles use `noslip_iterations: 5`, enabling the additional slip-correction stage. The Agent/script chooses approach→close→sustained contact→trial lift→arm transport→supported release. Cancellation retains grip; preload is applied once. Opening, lost grip contact and stable external support confirm placement; a later fall revokes it. Slip, deep penetration and non-grasp contacts refuse success. Each effector tracks one rigid body; shared-object dual-hand control, suction, soft hands and articulated payloads are unsupported.
cuRobo plans with configured robot spheres and scene obstacle approximations. Successful plans go directly to Genesis execution, without independent FCL initial-state, endpoint, or path checks. Uncontrolled supports must be continuous leaf joints with centered spherical collision geometry. Dynamic obstacles remain stationary and monitored. Conservative payload spheres follow the measured tool-relative pose. Lift planning excludes the measured contact support to allow departure; Genesis still simulates physical contacts. Planner success does not establish exact mesh clearance or a successful grasp; execution feedback reports the physical outcome.

See [backend reference](simulaiton-guide.md) for profile fields. Contact/payload readback runs each tick to detect slip; large-scene overhead remains unmeasured, with no real-time guarantee.


### Collision-aware pick execution

`pick_target` screens pre-grasp, grasp, and lift poses for reachability using cached cuRobo IK. Each of the three motions is planned with self-collision and environment avoidance by cuRobo MotionPlanner, then executed through Genesis joint control without a separate FCL gate. It does not use the direct-IK interpolation mode. A motion failure returns immediately; another candidate is not executed automatically. Lift planning includes the measured payload before closure and execution; success still requires measured contact, lift, and stable holding. The tabletop `moz1-graspgenx.json` profile starts both arms in mirrored folded poses, without pre-positioning the right arm near the table.

The scene owns persistent IK and planning workers. Reserved per-effector payload sphere slots and fixed obstacle cache capacities allow current geometry to update without rebuilding CUDA graphs during pick/release. A model, group, collision topology, or cache-capacity change still rebuilds the backend. Both workers use the installed matching NVRTC libraries; no model download is needed. Per-request artifacts retain initialization reuse, solver, collision-validation, and execution timing. On Linux, Genesis physics uses CPU, while Nyx rendering and cuRobo solvers remain on CUDA; the MOZ1/Panda profiles restore `noslip_iterations: 5`. Reload the simulation backend after updating the resolved runtime profile to apply physics-solver settings.

Robot loading warms MotionPlanner and current-pose IK for the groups declared by `grasp_pose_backends`, without executing motion. `arm_planning_ready` is published afterwards. Startup `arm_planning_warmup` and `warmup.json` retain this cost; initialization moves to loading rather than disappearing. Workers cache backends per group and refresh measured geometry on later requests. Successful and failed plans retain `prepare_s` (including `backend_create_s` and `warmup_s`), `solve_s`, `postprocess_s`, and `plan_including_prepare_s`. IK records each solve and request wall time; execution records `command_wall_s` and `execution_and_settle_s`.

MOZ1 declares RoboSim's adjacent shoulder sphere pairs through `collision_source.adjacent_self_collision_pairs`: `waist03` with `left02/03` and `right02/03`. These exclusions describe designed sphere overlap and are retained in collision provenance. Other robot and environment collision checks remain in cuRobo; no FCL gate is added.

`moz1-graspgenx.json` uses `collision_sphere_overrides` to load `moz1-gripper-spheres.yaml`. Only the distal fingers and rigid wrist/palm geometry are refitted with cuRobo's official MorphIt tool. Each side uses its actual loaded collision geometry; their convex decomposition policies differ. Geometry previously assigned to the virtual gripper-base frames is represented on `left07/right07`; tool frames and control settings are unchanged. The file records fitting parameters and explicit 0.15–0.50 mm finger coverage allowances. It adds no self-collision exclusions.

Overrides are bound to both the original collision-source hash and the prepared-model hash; changed sources, override files or prepared models are rejected until the geometry is refitted and the resolved profile regenerated. This binding belongs to the grasp profile's collision policy; ordinary `moz1.yaml/json` profiles retain the original XRDF. Static fit metrics do not establish Chrome grasp acceptance. Opposing finger spheres still overlap at full empty closure; retain this limitation with the geometry report.
