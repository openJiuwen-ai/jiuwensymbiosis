# Genesis arm planning and grasp evidence

cuRobo V2 plans; the existing Genesis scene alone owns motors, physics and measured stopping. Stop the base before arm planning; mobile whole-body planning is unsupported. ArmMotion/EndEffectors/GraspEvidence have no robot-name branches (wheel-base control remains MOZ1-specific): MOZ1/Panda joints, tools, gains and collision sources are profile data, not defaults for other bodies or hardware.

## Installation and entry point

Use `pip install -e '.[genesis,genesis-planning]' --extra-index-url https://download.pytorch.org/whl/cu130` in a dedicated environment. Separately build [cuRobo V2 commit 78fd485](https://github.com/NVlabs/curobo/tree/78fd485fa82d9b9a063fb4985e371814587e666a) using its upstream CUDA instructions (tested version `0.8.0.post1.dev43`). This Apache-2.0 checkout exposes `MotionPlanner`/`MotionPlannerCfg`, not legacy `MotionGen`; its code/assets are not bundled here. Core imports no CUDA planner; dev installs python-fcl for CPU collision tests.
Set `MOZ1_XRDF` to an externally obtained XRDF matching the actual robot URDF, or `CUROBO_FRANKA_CONFIG` to the checkout's Franka config. Resolve `configs/simulators/planning/{moz1,panda}.yaml` with `planning_profile.load_profile` into JSON under `outputs/arm-planning/`; see the [Python example](../../zh/how-to/genesis-arm-planning.md). The loader expands paths/environment variables and records source hashes and exclusion rationale; workers inherit no arbitrary environment variables.
Only the Python `PreviewSettings`/`GenesisPreview.configure` interface accepts `planning_profile` with `robot_mode="moz1_wheels"`. The GUI has no planning configuration control. Fixed-arm loading is not implemented: Panda is a model/planner validation reference, not a runnable preview mode. New bodies need physical loaders and model/FK/collision/execution acceptance. MOZ1 motors must have valid authored limits (example effort=16.5, velocity≥0.6, lower≤-0.61); old zero-limit exports are rejected.

## Actions and recovery

Admitted ground-truth sessions expose `motion.joint`/`motion.tool_pose`, plus `grasp.parallel` when effectors exist; vision/RGB-D sessions do not. `sim_get_robot_state` includes measured joints, tools and per-effector evidence. `move_joint(targets)` uses absolute named radians/metres and holds omitted joints. `move_tool_poses(group, poses, speed=1)` requires all group tools as `[x,y,z,qw,qx,qy,qz]` in configured planning base_link metres/unit quaternion. `open_gripper(width_mm=80, *, effector=None)` / `close_gripper(force_n=None, *, effector=None)` share the hardware action vocabulary. Select a configured effector when multiple grippers exist; legacy single-gripper adapters retain positional width/force calls and reject named selectors. Genesis ignores width/force hints. Payload preconditions/effects use `payload.clear:<name>` / `payload.held:<name>` for named actions; aggregate held means any hand holds, clear requires all hands measured empty. Unknown remains unknown; closing is not grasp confirmation.
A separate CUDA process is killed on cancellation/90-second deadline. Ownership and leases use existing RPC. Quintic paths are checked for position/analytic derivative extrema and retimed without clipping; motors never teleport. Execution binds scene/model/base/static joints/payload/obstacles, brakes on failure and measures settling. Results separate plan_success/goal_reached/settled/stop_confirmation; numeric thresholds are in the Chinese guide.
Unknown stopping blocks commands and ownership release; unknown payload blocks planning, base motion and reset. Inspect reason/per-effector state and retain `arm-plans/<scene_instance_id>/<plan_id>/` and sibling `execution-<uuid>.json` under the state directory (default `~/.jiuwensymbiosis/genesis-preview`; every reset creates an instance directory). Release only after measured stable support. Persistent readback failure, a missing object or unconfirmed stopping requires an operator to stop/restart the simulation backend and revalidate the world; there is no evidence-clearing bypass or automatic open/retreat. Official hosts disable Recovery/HOME; custom Session hosts must exclude home and disable automatic recovery too. Automatic homing is unsupported. Evidence has no automatic retention policy; archive/clean it only after backend shutdown.
Effectors require independent bounded motors, disjoint contact groups and no overlap with arm joints; mimic followers remain passive. Optional noslip_iterations is experimental. The Agent/script chooses approach→close→sustained contact→trial lift→arm transport→supported release. Cancellation retains grip; preload is applied once. Opening, lost grip contact and stable external support confirm placement; a later fall revokes it. Slip, deep penetration and non-grasp contacts refuse success. Each effector tracks one rigid body; shared-object dual-hand control, suction, soft hands and articulated payloads are unsupported.
Sphere coverage is diagnostic. FCL checks actual loaded geometry and engine-eligible pairs; external exclusion lists cannot bypass it. Only configured support links may touch the floor; uncontrolled supports must be continuous leaf joints with centered spherical collision geometry. Dynamic obstacles must remain still and monitored. Payload geometry follows its measured tool-relative pose; cuRobo uses conservative spheres. A measured fixed support may be omitted only from the coarse planner: FCL still requires nearly vertical normals, ≤1 mm penetration and non-truncated contacts for payload/support, with no robot exemption. New supports may be rejected. Sampling and SDK pair filters are not continuous-collision or physical-success proofs. Historical trials do not validate this commit, independent dual-arm carrying, autonomous LLM tasks or hardware.

See [backend reference](simulaiton-guide.md) for profile fields. Contact/payload readback runs each tick to detect slip; large-scene overhead remains unmeasured, with no real-time guarantee.
