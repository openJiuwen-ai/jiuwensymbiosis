# Genesis 配置驱动的夹持与放置

夹持功能复用 `ArmMotion` 的场景所有权、租约、取消、停车确认和规划进程。`EndEffectors` 只写电机目标和读取接触；`GraspEvidence` 判断持物证据。两者不创建世界、不步进物理，也不把物体焊接到机器人。

## 接入新的本体

在[规划配置](genesis-arm-planning.md)添加 `effectors`，键是任意业务名称。每个夹爪配置：

- `tool`：模型中的工具链节。
- `joints`：独立驱动关节；每项含 `open`、`close`、`velocity`、`effort`、`kp`、`kd`、`tolerance`。转动单位 rad，移动单位 m；速度、力/力矩不得超过模型限值。驱动关节不能同时属于机械臂规划组。
- `contact_groups`：至少两个互不重叠的接触链节集合；必须同时接触同一个物体。模型的 mimic 关系由物理引擎处理，初始化控制器必须让 follower 保持被动，不重复写电机目标。

MOZ1 和 Panda 模板只是配置示例，控制代码没有本体名称白名单。当前实现针对平行/联动夹爪和单刚体负载；吸盘、柔性手、铰接物体需要自己的证据与控制实现，不能仅更换名称冒充支持。GUI 的任意本体加载范围没有因此扩大。

`contact_solver.noslip_iterations` 是可选的 Genesis 接触求解参数。示例为 5，以抑制软接触下的数值蠕变；该 SDK 功能是实验性的，有性能开销。未配置时保留引擎默认值。电机增益和接触参数均是仿真参数，不是厂家硬件规格。

## 动作与证据

实际场景接纳效应器配置后，ground-truth Agent 才得到共享 `set_gripper(effector, opened)` 动作及 `grasp.parallel` 能力。既有其他适配器的 `open_gripper` / `close_gripper` 参数保持不变。

推荐调用次序由 Agent 或测试脚本决定：

1. 用 `move_tool_poses` 到夹取姿态，`set_gripper(name, False)` 闭合。
2. 多面接触持续 0.15 s 后仅得到 `contact_confirmed`。闭合目标按配置速度持续推进至 `close`，包括指面已接触、动作已返回及机械臂抬升期间。Genesis 保持最终位置驱动，物体挡住指面时由位置误差产生持续夹紧力，关节输出受 `effort` 限制；实际指面接触力随几何和运动变化。
3. 沿已有规划接口试抬升至少 15 mm，并保持接触、工具相对物体位姿稳定，才得到 `holding_payload=True`。
4. 使用相同规划接口带载移动。回到支撑面、确认外部向上支撑力和稳定速度后，才允许 `set_gripper(name, True)`。
5. 开放到位、无夹持接触且外部支撑稳定 0.25 s，才报告 `placement_confirmed`；释放后的对象继续被观测，退离时掉落会撤销放置确认。

`sim_get_robot_state` 的 `effectors` 返回逐夹爪状态；`holding_payload` 是 true/false/unknown。`set_gripper` 不凭命令给 ExecutionMemory 添加 `payload.held`，世界状态读取实测结果。空夹失败；接触丢失 0.1 s、相对平移超过 3 mm、相对旋转超过 0.05 rad、非夹取链节接触或穿透超过 2 mm 都不能成为成功抓取。

已接纳的闭合在取消动作回报后仍继续向闭合端点施力，显式张开指令会终止该闭合驱动。未知持物不能继续规划；未测得支撑不能释放。持物或未知持物时拒绝底盘移动和场景复位，直到实现相应的负载扫掠检查。自动机械臂回家仍未开放。每个夹爪可以独立追踪一个对象；两个夹爪持同一个对象会拒绝，需要单独的闭链控制设计与验收。

## 带载几何与范围

规划快照把实际加载的负载网格及实测工具相对变换送到独立 FCL 检查，同时为 cuRobo 生成保守包围球。仅允许该负载接触配置中的夹取链节，其他机器人/世界碰撞仍检查。持物位姿或静止障碍物发生变化，旧计划失效。

负载球在接触面附近可能过于保守：已实际测得的固定支撑形状会从 cuRobo 粗模型中移除，但始终保留在独立全几何检查中。只有负载与该支撑面法向近似竖直、穿透不超过 1 mm 的接触被接受；机器人本体不享有该例外。当前物理验收是回到已测得的原支撑面；未接触过的新支撑面可能被保守规划拒绝，不能宣称支持任意目标放置。

这是离散轨迹采样检查，不是连续碰撞证明；接触引擎已有的配对过滤仍生效。实测单物体闭环、模型参数、视频、失败实验和遥测保存在 `outputs/grasp-integration/20261103/`。双臂各持一个物体、真实 LLM 自主抓放任务及硬件尚需独立验收。

## 完全闭合驱动的仿真验收

MOZ1 左右夹爪的闭合端点为 −0.0095 rad，电机力矩上限为 16.5 N·m。Panda 的直线关节闭合端点为 0 m，驱动刚度和阻尼参考 RoboSim 的 5000 N/m 和 500 N·s/m，输出上限取自 Genesis 所加载模型的 20 N。已有自定义配置中的 `preload` 不再参与目标计算。

MOZ1 固定底座右手使用上一轮的 GraspGenX 候选，在 Genesis 中重新执行 cuRobo 规划。每组先规划抬升，再闭爪，下一物理步开始抬升。实验在动作结束后评分。最后连续 2 秒（240 步）内，物体相对闭爪前升高至少 50 mm，且两侧指面接触力各超过 0.05 N，计为成功。

| 首轮工况 | 接触后锁定预压目标 | 持续向完全闭合端点驱动 |
|---|---:|---:|
| 方块、长方块、圆柱，各取 0°、30°、60° | 7/9 | 8/9 |
| HUAWEI 杏、石榴、草莓 | 1/3 | 3/3 |
| 合计 | 8/12 | 11/12 |

圆柱 30° 首次在预抓取规划阶段因场景状态变化而停止。沿用同一候选和参数补跑，物体持稳在起始位置上方 80.3 mm。包含这次补跑，共执行 12 次实际抬升，每次都通过持稳判据。各工况首轮各计一次。两轮同时调整了闭合策略、目标推进速度（0.15 → 0.6 rad/s）和力矩上限（8 → 16.5 N·m），因此结果反映整套配置的变化。水果使用模型表面点云和凸碰撞近似。

本地实验目录 `outputs/graspgenx-full-close-matrix/` 中的 `REPORT.md` 记录逐组结果，`videos.html` 提供包括中止与补跑在内的 26 段录像，`summary.json` 汇总动作阶段、物体位移、指面接触和电机力矩。独立 Panda 搬运及释放验证见 `outputs/graspgenx-full-close/measured.json`。这些实验产物按仓库约定保存在本地。
