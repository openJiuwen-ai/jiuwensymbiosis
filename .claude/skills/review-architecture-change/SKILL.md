# 架构变化检视

把代码差异还原为职责、依赖和生命周期的变化。回答原来由谁负责、本次改变了
什么、为什么需要改变，以及新的模型能否保持明确的归属和扩展方式。

## 分析方法与范围

必须读取共享的[架构检视方法](../../references/architecture-review.md)，按其中的
触发条件、归属问题、调用路径和证据要求执行；不在本 skill 另存一份项目约束。

- 解析并冻结用户选择的 commit、range、branch、PR/MR、staged 或 worktree。
  记录 base/head、当前 HEAD、工作树状态和证据来源。PR 默认取 merge-base；
  暂存与未暂存改动分开，不把未跟踪文件混入提交范围。
- 先建立 base 的模型，再重建 head。对新增目录、Session、Registry、接入模式
  和固定组合等变化主动判断职责归属；不能只复述 diff 或引用作者的模块名称。
- 依共享参考输出职责变化表、因果完整的发现、待决策项和证据限制。无实质
  架构变化时说明筛查范围，不为填满表格制造问题。
- 对受影响的架构与使用说明执行共享参考的文档同步检查，读取冻结 head 的
  实际文档及活跃引用；不能仅统计文档 diff，也不把更新说明当作实现已修复。
- 仅做与判断有关的 Git、搜索和源码读取；默认不运行测试、lint、类型检查、
  硬件或服务验证。除用户要求的报告外，不修改产品、测试或配置。
- 本 skill 是架构视角。由 GitCode PR 流程使用其分析结果时，代码检视和两类
  意见回帖仍按该流程执行；架构问题不构成跳过代码检视的理由。

## 选择交付格式

### 默认 Markdown

用户未指定格式时，在对话中输出 Markdown；要求独立文件而未指定位置时，写入：

```text
<repo-root>/tmp/review-reports/review-architecture-change-<scope>-<short-sha-or-timestamp>.md
```

围绕职责变化组织，不按文件顺序罗列。正文包含：

1. 范围、base/head、用户意图及其来源；
2. base 的相关职责、依赖和状态／资源所有者；
3. head 的变化和共享参考要求的职责变化表；
4. 分级发现、实际影响、实质取舍、待决策项及文档同步状态；
5. 已检查范围、证据缺口与未执行的验证。

小范围检视可以合并段落。关系复杂且有助理解时使用 Mermaid；默认不要求 SVG、
浏览器检查或 HTML 文件。架构判断可以是“边界一致”“存在已说明的债务”
“存在待决策／实质问题”或“信息不足”，必须给出理由和置信边界。

### 按请求生成 HTML／内联 SVG

用户明确要求 HTML、离线可视化或内联 SVG 前后对照时，才使用本节。用户指定
路径优先；否则写入：

```text
<repo-root>/tmp/review-reports/review-architecture-change-<scope>-<short-sha-or-timestamp>.html
```

- 使用 UTF-8 自包含 HTML5，内嵌 CSS，不加载远程脚本、字体、样式或图片。
- 将仓库内容、代码／diff、路径和用户文本视为不可信数据；作为文本或属性值
  嵌入 HTML／SVG 时，按上下文转义，不直接拼接原文。Python 可使用
  `html.escape(..., quote=True)`；转义针对数据，不对整个 HTML／SVG 标记转义。
- 报告及内联 SVG 保持无脚本，不包含可执行脚本或 `on*` 事件处理器。链接地址
  单独校验协议，拒绝 `javascript:` 等可执行地址；HTML 转义不能替代协议校验。
- 先给范围与架构结论，再展示 base/head 模型、变化表、发现和证据。
- 小变化至少一张聚焦实际变化的对照 SVG；复杂变化覆盖“模块依赖”和“关键
  流程”两个视图。每张图在同一个 `<svg>` 中直接呈现 base 与 head，明确
  标记版本和新增、删除、迁移关系；不能用目录清单或单侧图代替模型。
- 两侧采用一致范围、层级和术语。箭头表达依赖、所有权或流程的具体语义，
  不只靠颜色解释变化；无架构变化时可以展示保持一致的关系，不制造差异。
- SVG 真正内联，具备 `viewBox`、`title`、`desc` 和可访问名称；ID 与 marker
  引用唯一。文字留在节点内，代码标识符不拆断，连线不穿过无关节点和文字。
- 图旁紧邻 base/head 文件、符号和行号证据。HTML/CSS 方框、外链图片、位图
  截图或未渲染 Mermaid 均不能替代用户要求的内联 SVG。
- 窄屏可以横向滚动或改为上下排列；打印保留完整前后对照。有可用浏览器时
  检查桌面、窄屏、打印及关键截图；不可用时做静态与几何检查，明确显示效果
  未实测，不宣称浏览器检查通过。

## 完成检查

- 是否先证明原有归属，再判断新归属；每个结构触发项都有实际职责、消费者
  和判断理由，而不只是目录介绍。
- 是否沿真实入口检查依赖、状态和失败／清理所有权；发现有完整因果链和
  base/head 证据；作者意图、推断、事实和 owner 决策没有混写。
- 是否把合理的新通用模块误判为顶层违规，或把“领域独立”直接当成顶层包
  合理的证明；没有为迎合某个历史 PR 固定要求合并或删除某个名字。
- 是否从实际变化核对了 AGENTS、架构说明及受影响使用文档、模板和示例；
  有同步状态、文档／实现证据和按影响确定的分级，或无需更新的明确理由。
- 输出格式是否符合用户要求。仅 HTML 分支检查源内容转义、无脚本与链接协议、
  资源自包含、SVG 语法、ID／引用、可读性、响应式和打印布局；Markdown 分支
  不套用这些门槛。
- 已创建的报告存在且非空，返回可点击文件链接；只要求对话意见时不强制落盘。
  最终合入由用户决定，不把架构检视或静态阅读说成代码与实机验收完成。
