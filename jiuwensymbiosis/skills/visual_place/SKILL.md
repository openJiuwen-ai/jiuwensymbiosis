# visual_place — 视觉/坐标引导放置

## 何时启用

同时满足：

1. 用户指令含"把（手上的 / 刚抓的）X 放到 Y / 放下 / 放进去"等放置意图。
2. `api.capabilities` 含**至少一种抓取能力**（`grasp.parallel` / `grasp.suction` / `grasp.dual_arm`）；放置点靠视觉定位时还需 `vision.detection`。
3. 已注册 `robot_control`。
4. **前置：末端已抓住目标物**（刚跑完 `visual_pick`，或上层已显式抓住）。不满足则**不要**启用——会让末端在空中释放。

## 放置目标来自用户任务

放置目标（目的地 / 放置面）的名字从用户这句任务里识别（"放到白色桌子上"→ 目标是"白色桌子"），作为下文检测 / 感知动作的 `object_name`。用户只说任务、不另传参数；**不要**套用本文示例里的名字。

## 动作映射表（按你的能力选行，占位符照此替换）

下文用 `<感知放置面>` / `<放置>` 这类占位符指代动作。**按【机器人能力】选你那一行**，替换成【可用动作】清单里真正存在的那个名字；清单里没有的变体一律不能输出。

| 你的能力 | `<感知放置面>` | `<放置>` |
|---|---|---|
| `grasp.parallel` | `get_grasp_info_simple` | `open_gripper` |
| `grasp.suction` | `get_grasp_info_simple` | `deactivate_suction` |
| `grasp.dual_arm` | `locate_for_place` | `dual_arm_place` |

会移动的本体（`motion.base`）另有一个占位符：

- `<搜索并驱近放置面>`（`motion.goal`）→ `approach_for_place`：**一步完成**"看不到就原地扫掠搜索 → 按感知方位转正 → 驶近到手臂可放距离"。已在可放范围内则不动（`status=in_range`）。

> **`_for_place` 是按「接下来要放」选的，不是按「那东西是不是桌子」选的。**
> 要放到货架上、放到另一个盒子上、放到椅子上——统统用 `_for_place` 那一支，
> 因为要判的是**落点**（高度够不够、放得下放不下、近边在哪好对正）。
> 同一个盒子，要搬走它时用 `_for_grasp`，要往它上面放东西时用 `_for_place`。

### 用参照物锁定「哪一个」放置面（`reference` + `relation`）

任务里常带一个**空间关系**来指认目标：「棕盒**上**的白箱」「帽子**旁边**的盒子」。这时给检测 / 搜索类动作加两个参数：

- `reference`：参照物的英文名（**只在任务真的点了参照物时才加**——写一个现场没有的参照物会让检测直接失败，不会退回普通搜索）。
- `relation`：`object_name` 相对 `reference` 的关系，取值**只能**是 `on` / `under` / `beside` / `near`，默认 `on`。

| 任务里的说法 | relation | 例子 |
|---|---|---|
| 在…上面、放在…上 | `on` | 「棕盒上的白箱」→ `object_name="white box", reference="brown box", relation="on"` |
| 在…下面；**有…在上面的那个** | `under` | 「放着杯子的那张桌子」= 杯子下面的桌子 → `object_name="table", reference="water cup", relation="under"` |
| 旁边、挨着、紧邻 | `beside` | 「帽子旁边的盒子」→ `object_name="box", reference="hat", relation="beside"` |
| 附近、周围、那一带 | `near` | 「门口附近的箱子」→ `object_name="box", reference="door", relation="near"` |

- `beside` 要求两者**高度相当**（挨在同一张台面上）；只是水平方向离得近、高度差很大时用 `near`。
- 关系一律读作「`object_name` <relation> `reference`」——方向别写反。
- 只有这四个值合法，`left_of` / `in_front_of` 这类**依赖观察视角**的说法不在其中（机器人一移动就不成立了）；遇到时改用最接近的合法值或干脆不加参照物。

## 放置方式（按你的抓取能力选一支，选定后只看你这一支）

### 支 A — 夹爪 / 吸盘臂（`motion.cartesian` + `grasp.parallel` 或 `grasp.suction`）

放置高度用检测返回的 `place_z`（= 放置面高度 + 已配置堆叠偏移，**已算好**），**不要**自己拿 `position.z` 加减。

放置点 `(px, py, place_z)` 来源二选一：
- **已知坐标**：visual_pick 阶段在 home 处已把放置目标坐标一并读好（腕部相机推荐做法）→ 直接用。
- **需定位**：`<感知放置面>` 传 `{"object_name": "<放置目标>"}` 拿 `px,py,place_z`。⚠️ 此时末端挂着物体，**不能** `home` 重拍（会拖件 / 遮挡），就地在搬运高度拍；`score < 0.4` 直接转「失败处理」。

| # | action | params | 目的 |
|---|---|---|---|
| 1 | `goto_xyzr` | `{"x":px,"y":py,"z":"place_z + 60"}` | 横移到放置点正上方（lift ≈ +50~80mm）。 |
| 2 | `goto_xyzr` | `{"x":px,"y":py,"z":place_z}` | 降到放置高度 `place_z`（检测给的，别改）。 |
| 3 | `<放置>` | `{}` | 松开物体。 |
| 4 | `goto_xyzr` | `{"x":px,"y":py,"z":"place_z + 60"}` | 提回搬运高度，避免拖到刚放下的物体。 |
| 5 | `home` | `{}` | 回 home，任务结束。 |

### 支 B — 双臂（`grasp.dual_arm`）

放置就是**一个 `<放置>`**（复合动作，内部完成对位 → 下放 → 松手）；放置面高度由 `<感知放置面>` 感知并被 `<放置>` 直接消费，几何字段不必回传，参数省略即可。**找放置面用 `<搜索并驱近放置面>` / `<感知放置面>`，绝不用 `locate_for_grasp`**——后者量的是抓取点（近面、面法向），不含落点高度和 footprint，而且是单次检测、看不到就失败。

放置面的获取按【有无底盘】走对应的**一条完整流程**：

#### 有底盘（`motion.base`）

放置目标常**不在当前视野**，所以**必做**下面这串（`<搜索并驱近放置面>` 打头，它就是"看不到就搜索"；**不是可选步、不能跳过**）：

| # | action | params | 目的 |
|---|---|---|---|
| 1 | `<搜索并驱近放置面>` | `{"object_name": "<放置目标>"}`（任务用参照物指认了放置面就按上表加 `"reference"` + `"relation"`） | 搜索→对准→驶近到可放距离，一步到位。失败 `surface_not_found` 则不盲放、转「失败处理」。 |
| 2 | `<感知放置面>` | 与第 1 步**同样的**参数 | 底盘移动后**重新感知**放置面。 |
| 3 | `<放置>` | `{}` | 双臂放下并松手。 |
| 4 | `home` | `{}` | 回安全位姿（已在 home 则不动）。 |

#### 无底盘 / 固定本体

本体不能移动、无法转身搜索或驶近，只用当前视野：

| # | action | params | 目的 |
|---|---|---|---|
| 1 | `<感知放置面>` | `{"object_name": "<放置目标>"}` | 感知当前视野内放置面；不在视野则失败、**不硬放**、转「失败处理」。 |
| 2 | `<放置>` | `{}` | 双臂放下并松手。 |
| 3 | `home` | `{}` | 回安全位姿（已在 home 则不动）。 |

## 结束状态

末端空载、物体落在放置面、机械臂在安全位姿。

## 失败处理

放置期失败代价比抓取期大（物体已悬空），按优先级：

1. **定位 / 感知放置面失败**（未找到 / 未识别 / 置信度低）：物体仍在手上，**不要**强行释放。报"放置面未找到 / 未识别"，交回上层（可换更具体描述或改坐标重来）。
2. **落点 / 放下失败**：**不要**原地释放。先用你这支自己的动作把物体抬回 / 退回安全高度、再回安全位姿，然后上报。
3. **收尾（回位）失败**：再试一次回安全位姿；仍失败报"放置成功但回位失败，需手动复位"。

## 与 Rails 的协作

- **SafetyRail**：放置点 z 常比抓取点低，`place_z` 要算对，否则被 `z_min_safe` 拦下。
- **RecoveryRail**：兜底 home + release；本 skill「失败处理」**克制释放**，就是为了不与它双重释放。

## Anti-patterns

- ❌ 末端未持物就启用本 skill：会在空中释放，下游以为放好了。
- ❌ 失败后立即释放：可能把物体丢在错误位置——先抬回搬运高度。
- ❌ 输出不在你能力/动作清单内的动作。
