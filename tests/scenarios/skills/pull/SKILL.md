# pull — 拉开（门 / 抽屉 / 柜门）

## 何时启用

同时满足：

1. 任务需要**先打开某个遮挡物**才能拿到目标：柜门 / 抽屉 / 冰箱门关着，目标在里面。
2. 手上**空载**（`payload.clear`）——拉门要用手，持物时不能拉。
3. 已注册 `robot_control`。

**典型触发信号**：任务用 `in` 关系指认目标（「柜子**里**的箱子」），而【场景感知】里
参照物（柜子）看得到、目标却在【未见】里——目标被关在里面，先 `pull` 打开再抓。

## 标准 Workflow

| # | action | params | 目的 |
|---|---|---|---|
| 1 | `approach_for_grasp` | `{"object_name": "<被拉物>"}` | 驶到可操作距离（看不到就扫掠搜索）。无底盘本体跳过。 |
| 2 | `pull` | `{"object_name": "<被拉物>"}` | 拉开。`distance_m` 可省略，默认按物体类型取。 |

`<被拉物>` 是门 / 抽屉 / 柜门本身（`cabinet` / `cabinet door` / `drawer`），**不是**里面的目标物。

## 结束状态

被拉物已打开，里面的东西暴露在视野中；手上仍空载，可以接 `visual_pick`。

## 失败处理

- `pull` 返回失败（够不到 / 把手未找到 / 拉不动）：报"拉开失败"，**不要**硬抓里面的东西
  （门还关着，抓取必然失败或碰撞），交回上层。

## Anti-patterns

- ❌ 持物时 `pull`：手上有东西拉不了门，且会掉件（契约 `requires: payload.clear` 会直接拒绝）。
- ❌ 用 `pull` 去拉要搬运的目标物：拉开是给容器/门用的，搬运目标请走 visual_pick。
- ❌ 门还关着就去 `<检测目标>` / `<抓取>` 里面的东西。
